Enable Portal Integrations

HR Suite Settings › Saudi Portal Credentials · Configure once; used by all portal calls
Saudi Portals
Path: HR Suite → Settings → HR Suite Settings → Saudi Portal Credentials section

Before using any Saudi portal button, enter credentials here. Each portal has its own section. Credentials are encrypted at rest — they are never exposed in logs.

1
Required · Data — Muqeem section
Muqeem API Username / Password / Establishment ID
Obtained from the MOI Muqeem employer portal. The Establishment ID is your MOI registration number.
💡 Contact your PRO (Public Relations Officer) or MOI account manager for Muqeem API credentials.
2
Required · Data — Qiwa section
Qiwa Client ID / Client Secret / Establishment Number
Generated from the Qiwa developer portal (qiwa.sa). The system fetches and caches the OAuth2 token automatically in Redis.
3
Required · Data — GOSI section
GOSI API Key / Secret / Establishment Number
From the GOSI employer API portal (gosi.gov.sa). All contribution submissions and registration calls are signed with these credentials.
4
Required · Data — Mudad section
Mudad API Key / Establishment ID / IBAN / Bank Code
From the Mudad WPS portal. The IBAN and Bank Code are embedded in the SAMA SIF file generated for WPS submissions.
🔴 Incorrect IBAN or bank code will cause WPS file rejection. Verify with your Finance team before saving.
After saving
✓
Save Settings
Save the HR Suite Settings document. All portal buttons on Employee forms, GOSI Contribution forms, Payroll Entry, and the daily schedulers will now use these credentials automatically.

UAE Employee Form

Employee › UAE Statutory group · Country-resolved buttons replace SA-specific groups
Global
Path: Employee → open a UAE employee record (Company.country = AE or Employee.work_country = AE)

When you open an Employee record whose resolved country is AE, HR Suite replaces the SA-specific button groups (Muqeem, Qiwa, GOSI) with a "UAE Statutory" group containing the relevant UAE compliance actions. This happens automatically on every page refresh — no configuration on the Employee record is needed.

1
Observe on form load
UAE Statutory group appears — SA groups absent
Open a UAE employee record. Scroll down the form. You will see a "UAE Statutory" section instead of Muqeem, Qiwa, or GOSI groups. This is the country-detection chain in action: HR Suite called the country resolution API on page load and rendered the correct buttons.
💡 If you see SA groups on a UAE employee, check that the company's country is set to AE in the Company DocType, and that the employee has no conflicting Employee.work_country set to SA.
2
Button · UAE Statutory group
GPSSA Contribution
For UAE nationals: opens or creates the GPSSA Contribution record for this employee. Rates: 5% employee + 12.5% employer. For expatriates: opens the DEWS/Gratuity record instead (the button label changes based on nationality).
3
Button · UAE Statutory group
Work Permit
Opens the UAE work permit and Emirates ID record for this employee. Similar to the SA Muqeem Iqama record, but for UAE residency documentation.
4
Button · UAE Statutory group
Settlement Breakdown
Opens a dialog showing the AE Gratuity calculation for this employee using Art. 51/132 — 21 calendar days per year for the first 5 years, 30 days per year thereafter. The breakdown uses the current last basic salary from the Salary Structure Assignment.
Sara Al-Mansoori · 4 yrs service · AED 22,000 basic → Gratuity: AED 61,600
💡 The Settlement Breakdown dialog is a live preview — it updates automatically if the salary or service dates change. It does not create any document; it is for reference only until Employee Separation is submitted.
5
Observe · Contract banner
Country Employment Contract banner (AED currency)
The contract banner at the top of the form shows the Country Employment Contract (not Country Employment Contract) and displays the salary in AED. This currency is resolved from the Company's default currency for the AE entity.

Auto EOSB on Separation

HRMS › Employee Separation · On submit, End of Service Benefit is auto-created using country formula and Employee.relieving_date
Global
Path: HRMS → Employee Separation → open or create record → Submit

Employee Separation in HRMS is the trigger point for HR Suite's settlement calculation hook. When the record is submitted, HR Suite intercepts the on_submit event, resolves the employee's country, runs the correct formula, and creates the End of Service Benefit record automatically — using Employee.relieving_date as the settlement date.

1
Pre-requisite
Employee.relieving_date must be set
Open the Employee record and ensure the Relieving Date field is filled with the employee's last working day. The auto-created EOSB record will use this date as its settlement date.
Khalid Al-Rashidi · Relieving Date: 31 Jul 2026
🔴 If Relieving Date is blank, the settlement record will be created with today's date, which may not match the correct last working day. Always set Relieving Date before submitting Employee Separation.
2
Required · Select
Separation Type Select
Resignation / Termination (Without Cause) / End of Contract / Retirement. This feeds into calculate_settlement() and determines the applicable entitlement fraction.
Khalid: Resignation (SA → ⅓ month/yr for <5 yrs) Sara: End of Contract (AE → full gratuity at 21 days/yr)
3
Action
Submit the Employee Separation record
Click Submit. The HRMS on_submit hook fires instantly. HR Suite resolves the employee's country, calls calculate_settlement() with the correct country dispatch, and creates the End of Service Benefit record.
💡 The entire process happens synchronously — by the time the submit confirmation dialog closes, the EOSB record already exists and is linked in the document's "Links" section.
4
Verify · Linked documents
End of Service Benefit — auto-created
After submit, scroll to the Links section of the Employee Separation form. You will see the auto-created End of Service Benefit record. Open it to review the amount, formula used, and settlement date.
Khalid (SA) → EOSB-2026-0041 · SAR 21,000 · Art. 84 · Date: 31 Jul 2026 Sara (AE) → EOSB-2026-0042 · AED 61,600 · Art. 51/132 · Date: 30 Sep 2026 Priya (IN) → EOSB-2026-0043 · INR 293,269 · Gratuity Act 1972 · Date: 15 Aug 2026
5
Note · SA employees only
Muqeem Final Exit — initiate after EOSB is settled
For Saudi Arabia expatriate employees only: after the EOSB is paid and Exit Clearance is complete, navigate to the Employee form → Muqeem group → Initiate Final Exit to submit the final exit request via the Muqeem API.
💡 For AE, BH, IN, and OM employees, work permit cancellation is handled via the respective country's statutory group buttons on the Employee form, not via Muqeem.
